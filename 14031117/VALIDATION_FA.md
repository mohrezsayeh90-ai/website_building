# آزمون نسخهٔ محلی مبتنی بر بکاپ 14031117

این گزارش، اجرای رابط محلی را تأیید می‌کند و ادعای بازیابی دیتابیس یا راه‌اندازی سایت عملیاتی اصلی نیست.

## مرجع

آخرین آرشیو ارسالی کاربر با نام 14031117.rar، حجم ۴۳۰٬۵۸۰ بایت، حاوی ۱۴۲ فایل PHP و ۲۶ فایل JavaScript است. SHA-256 آرشیو دریافتی و تک‌تک فایل‌ها در backup-manifest.json ثبت شده است. تمام ۱۶۸ فایل اصلی بدون تغییر باقی مانده‌اند و قالب‌های پروژه مستقیماً از app/views همین بکاپ اجرا می‌شوند.

فایل‌های اصلی از نظر محتوا با نسخهٔ قبلی 14031117 یکسان بودند. خود فایل فشردهٔ جدید با آرشیو قبلی بایت‌های یکسان نداشت؛ کپی دقیق جدید در BACKUP_RECEIVED.rar نگهداری شده است. هیچ فایل دیتابیس یا رکورد پروژه در آرشیو دیده نشد.

## نتایج

۲۹ بررسی موفق و صفر شکست در اجرای نهایی ثبت شد؛ جزئیات در validation/results.json موجود است:

- حالت عادی در دسکتاپ ۱۴۴۰×۱۰۰۰ و موبایل ۳۹۰×۸۴۴، پروژهٔ ساختگی نشان نمی‌دهد و جدول‌های پروژه خالی‌اند.
- دادهٔ نمونه فقط با انتخاب صریح حالت demo نمایش داده می‌شود و به‌عنوان دادهٔ بکاپ معرفی نمی‌شود.
- جست‌وجو، تب پروژه‌های تکمیل‌شده و رفتن از فهرست به شناسنامهٔ متناظر کار کردند.
- پیش‌نویس محلی پس از reload ماندگار بود، از پروژهٔ دیگر جدا ماند و با بازگردانی نمونه حذف شد.
- خروج از حالت نمونه به جدول خالی حالت بکاپ برگشت.
- در جریان‌های بررسی‌شده خطای JavaScript یا پاسخ HTTP ناموفق ثبت نشد.
- پروژهٔ نمونه در حالت عادی، پروژهٔ ناشناخته، دسترسی وب به مدل PHP، آرشیو اصلی و فایل دادهٔ نمونه پاسخ 404 دادند؛ فایل‌های خام از وب سرو نمی‌شوند.
- آرشیو دریافتی و هر ۱۶۸ فایل اصلی با hash مرجع برابر بودند. data/projects.json واقعاً خالی بود.

قالب قدیمی iframeهایی برای پنجره‌های وابسته به دیتابیس پیش‌بارگذاری می‌کرد. در خروجی renderer، URL آن‌ها فقط به‌صورت metadata نگهداری می‌شود و بارگذاری خودکار انجام نمی‌شود. فایل قالب اصلی تغییر نکرده است. پنجره‌های وابسته به اطلاعات واقعی پیام محدودیت نشان می‌دهند.

router.php و دو قالب منتخب با PHP 8.4.24 بررسی نحوی شدند؛ JavaScript محلی نیز بررسی نحوی شد. نصب محلی PHP از ابزار قبلی قابل استفاده بود و اسکریپت نصب دوباره runtime را تشخیص داد. اجرای برنامه به SQL Server یا اطلاعات ورود واقعی متصل نشد.

سرویس‌های آزمایشی متوقف شدند و نسخهٔ مبتنی بر بکاپ با دستور مستند bash start-local.sh روی پورت پیش‌فرض دوباره شروع شد. چهار درخواست محتوایی برای حالت عادی و نمونه پس از راه‌اندازی مجدد موفق بودند.

## حدود نتیجه

خود START_LOCAL.cmd روی ویندوز در محیط لینوکسی اجرا نشده است. فایل‌های PHP اجرایی سیستم کاربر و همهٔ assetهای ویندوز اینجا دریافت نشده‌اند. ZIP در یک مسیر جدا استخراج شد و سه پوشهٔ 14031117، Apache24 و php کنار هم قرار گرفتند. با PHP لینوکسی، اجرای بستهٔ استخراج‌شده و خواندن خودکار یک فایل asset کنترل‌شده از پوشهٔ همسایهٔ Apache24 تأیید شد؛ فایل php.exe ویندوز در این آزمون اجرا نشد. حالت عادی و حالت نمونه نیز در بستهٔ استخراج‌شده پاسخ صحیح دادند. تصاویر validation در محیط ابری با assetهای fallback گرفته شده‌اند.

فهرست و شناسنامه قالب بکاپ هستند؛ سربرگ، منو و داشبورد محلی‌اند. فایل اصلی بکاپ هستهٔ System، index.php و پیکربندی را ندارد؛ این ابزار به‌جای بازسازی هستهٔ کامل فقط قالب‌های منتخب را با renderer جدا نمایش می‌دهد. ورود واقعی، ذخیرهٔ اصلی، ایمیل، گردش تأیید، SQL Server و گزارش‌های اصلی اجرا یا تأیید نشده‌اند. زمان ادعایی ۱۲ ساعت و یکسان‌بودن تاریخ assetهای بیرونی با کد بکاپ مستقلاً تأیید نشده است.

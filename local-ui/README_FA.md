# نسخهٔ محلی رابط پروژه‌های مهرآباد

این بسته برای بازکردن صفحات، بررسی ظاهر و تغییر جای دکمه ساخته شده است. فهرست پروژه‌ها و شناسنامهٔ پروژه از دو قالب PHP موجود در `bin.rar`، بدون تغییر در فایل قالب، رندر می‌شوند. داده‌های پروژه‌ها آزمایشی‌اند؛ اتصال به دیتابیس، ورود واقعی و گردش تأیید نسخهٔ اصلی بازسازی نشده‌اند.

## اجرا روی ویندوز شما

۱. پوشهٔ `local-ui` را در پوشهٔ `TEST`، کنار `Apache24` و `php` قرار دهید:

```text
TEST/
├── Apache24/
│   └── htdocs/mehrabad/assets/...
├── php/
│   └── php.exe
└── local-ui/
    ├── START_LOCAL.cmd
    ├── router.php
    └── public/
```

۲. روی **START_LOCAL.cmd** دوبار کلیک کنید. مرورگر پس از آماده‌شدن صفحه باز می‌شود. پنجرهٔ اجرا باید باز بماند؛ برای توقف Ctrl+C بزنید. نیازی به نصب Node.js، اجرای Apache، تغییر مسیرهای D: در Apache یا نصب دیتابیس نیست. از PHP موجود شما با تنظیم `-n` استفاده می‌شود تا تنظیمات قدیمی و افزونه‌های نامرتبط دخالت نکنند.

۳. وارد «پروژه‌ها» شوید و آیکون شناسنامه را در ستون عملیات بزنید. هر پروژه به اطلاعات نمونهٔ مخصوص خودش متصل است. دکمه‌های EPL و DPL فعال به جدول آزمایشی همان پروژه می‌روند. این دو جدول، فرم کامل سایت اصلی نیستند.

۴. در شناسنامه، «ذخیرهٔ پیش‌نویس محلی» اطلاعات ورودی را در مرورگر ذخیره می‌کند. بعد از بازکردن مجدد همان پروژه، اطلاعات برمی‌گردند. «بازگردانی اطلاعات نمونه» پیش‌نویس همان پروژه را پاک می‌کند. اطلاعات اصلی سایت تغییر نمی‌کند. این ذخیره‌سازی جایگزین دیتابیس نیست و به همین مرورگر و همین آدرس محلی وابسته است.

اگر پورت ۸۰۳۳ در استفاده باشد، سرور شروع نمی‌شود؛ پنجرهٔ خطا را برای بررسی نگه دارید. برنامه را فقط یک بار اجرا کنید. این ابزار صرفاً برای اجرای محلی روی loopback است و برای انتشار روی اینترنت طراحی نشده است.

## استفاده از فایل‌های ظاهر موجود روی سیستم

برنامه به‌صورت خودکار مسیر `../Apache24/htdocs/mehrabad` را پیدا می‌کند. اگر پروژه را جای دیگری قرار دادید، `local.example.json` را با نام `local.json` کپی کنید و `site_root` را مطابق مسیر واقعی تغییر دهید؛ فقط مسیر پوشه است و رمز نیاز ندارد. متغیر محیطی `MEHRABAD_SITE_ROOT` نیز قابل استفاده است.

در این حالت CSSهای اصلی، فایل `assets/lib/css/outputWind.css`، فونت و برخی تصاویر ثابت و آیکون‌های موجود از همان پوشه خوانده می‌شوند. هیچ فایل آن پوشه تغییر نمی‌کند. کنترلرها، مدل‌ها، فایل‌های تنظیمات و پیوست‌های کاربران توسط این ابزار اجرا یا سرو نمی‌شوند.

اگر فایل ظاهر در دسترس نباشد، از CSS و آیکون و فونت جایگزین همراه بسته استفاده می‌شود. CSS عمومی و ویژه، همان نسخهٔ دریافت‌شده هستند؛ utility CSS جایگزین با Tailwind ساخته شده است. سربرگ، منوی کناری و داشبورد اجرای محلی‌اند؛ معادل کامل سربرگ اصلی نیستند. بدون تصویر مرجع و همهٔ فایل‌های اصلی، تطابق دقیق ظاهر قابل ادعا نیست.

## فایل تغییر دکمه

| صفحه | فایل |
| --- | --- |
| فهرست پروژه‌ها | `source/project/prjman.php` |
| شناسنامه و نوار ابزار | `source/project/showprj.php` |
| رفتار دکمه‌ها در نسخهٔ محلی | `public/ui/local.js` |
| تنظیمات نمایش محلی | `public/ui/local.css` |
| پروژه‌های نمونه | `data/projects.json` |

قالب‌های داخل source کپی مستقیم فایل‌های دریافتی هستند. برای انتقال تغییر نهایی به سایت اصلی، همان تغییر باید در فایل متناظر `app/views/project/` اعمال و با نسخهٔ واقعی آزمایش شود. این ابزار مجوزها، پایگاه داده یا عملیات اصلی را تأیید نمی‌کند.

عملیات نیازمند ایمیل، تأیید، خروجی Excel/PDF و اسناد واقعی پیام محدودیت نشان می‌دهند و موفقیت ساختگی ثبت نمی‌کنند. فایل DCC.php و مقدار محرمانهٔ داخل آن وارد این بسته نشده‌اند.

## توسعه و بازسازی CSS

برای اجرای بسته نیازی به نصب npm نیست؛ خروجی CSS و آیکون‌ها همراه آن است. فقط برای بازسازی utility CSS:

```bash
cd local-ui
npm ci --ignore-scripts
npm run build
```

روی لینوکس با PHP 8.2 یا بالاتر، `bash start-local.sh` را اجرا کنید. هر وظیفهٔ ابری از قبل محیط جدا دارد؛ از checkout موجود استفاده کنید و بدون درخواست کاربر worktree نسازید.

قالب‌های رندرشده و محدودیت‌ها در این راهنما توضیح داده شده‌اند؛ نتایج اجرای واقعی این بسته در `VALIDATION_FA.md` ثبت می‌شوند. اجرای Windows launcher در محیط لینوکسی آزمایش نشده است.
